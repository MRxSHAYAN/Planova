1. WHAT IS PLANOVA
================================================================================

A web platform for managing expos, trade shows, and conferences in Pakistan.

Three user types:
  ATTENDEE  — browse expos, register for sessions, manage profile
  EXHIBITOR — apply to expos, manage booth, build company profile
  ADMIN     — manage the whole platform (users, expos, applications)

The public website shows upcoming expos and info. Each role has a private
dashboard after login.

4. HOW TO RUN
================================================================================

Requirements: Node.js v18+, MongoDB (local or Atlas)

STEP 1 — Install MongoDB
  Local: download from mongodb.com/try/download/community
  Atlas:  create free cluster at mongodb.com/cloud/atlas

STEP 2 — Install dependencies
  cd server && npm install
  cd client && npm install

STEP 3 — Create server/.env
  See Section 5 below for all required values.

STEP 4 — Get Gmail App Password for SMTP
  Google Account > Security > 2-Step Verification > App Passwords
  Create one, copy the 16-char password, remove all spaces, put in SMTP_PASS

STEP 5 — Seed the database
  cd server
  node seed.js
  Creates admin, exhibitor, and attendee demo users.

STEP 6 — Start both servers
  Terminal 1:  cd server && npm run dev     (port 5000)
  Terminal 2:  cd client && npm run dev     (port 5173)

STEP 7 — Open the app
  http://localhost:5173

Vite proxies /api/* to localhost:5000 automatically (vite.config.js).

7. API ROUTES
================================================================================

Base: http://localhost:5000

--- PUBLIC ---

POST /api/auth/register                 create account, send OTP email
POST /api/auth/verify-otp               verify OTP, activate account, get token
POST /api/auth/resend-otp               resend registration OTP
POST /api/auth/login                    login, returns token
POST /api/auth/admin/login              admin-only login
POST /api/auth/forgot-password          send OTP to email for password reset
POST /api/auth/reset-password           verify OTP, set new password
POST /api/newsletter/subscribe          add email to newsletter list

--- PROTECTED (requires Authorization: Bearer token) ---

GET  /api/auth/profile                  get current user
PUT  /api/auth/profile                  update name, phone, city, company, avatar, etc.
POST /api/auth/request-email-change     send OTP to new email
POST /api/auth/confirm-email-change     verify OTP, swap email in DB
POST /api/auth/request-password-change  send OTP to current email
POST /api/auth/confirm-password-change  verify OTP, save new password

--- ADMIN ONLY ---

GET  /api/auth/stats                    user count stats
GET  /api/auth/users                    all users from DB
PUT  /api/auth/users/:id/status         toggle user active/inactive
GET  /api/newsletter/subscribers        all newsletter subscribers
DELETE /api/newsletter/subscribers/:id  remove subscriber

GET  /api/health                        server + DB status

9. AUTH & OTP SYSTEM
================================================================================

HOW LOGIN/REGISTER WORKS:
  1. Register > OTP sent to email
  2. Enter OTP > account verified > token returned
  3. Token stored in localStorage as "planova_token"
  4. Every API call sends: Authorization: Bearer token
  5. Logout clears localStorage

AUTHCONTEXT (client/src/context/AuthContext.jsx)
  user           logged-in user object
  login(data)    stores token + user in localStorage
  updateUser(f)  updates stored user so sidebar refreshes immediately
  logout()       clears localStorage

USEPROFILE HOOK (client/src/hooks/useProfile.js)
  Fetches fresh data from GET /api/auth/profile
  Returns { profile, loading, error, refresh }
  Also exports: updateProfile(data), initials(name)

OTP USES:
  Registration verify   POST /register > OTP > POST /verify-otp
  Email change          POST /request-email-change > OTP > POST /confirm-email-change
  Password change       POST /request-password-change > OTP > POST /confirm-password-change
  Forgot password       POST /forgot-password > OTP > POST /reset-password


================================================================================
10. PASSWORD REQUIREMENTS
================================================================================

  At least 7 characters
  At least one letter (a-z or A-Z)
  At least one special character (!@#$%^&* etc.)

Enforced on:
  - Register
  - Forgot password / reset password
  - Password change from profile

The Register page and ForgotPassword page show live hints as you type.


================================================================================
11. EMAIL SYSTEM
================================================================================

All emails sent via nodemailer using SMTP (works with any provider).
Transporter created fresh on each send so env var changes take effect immediately.

The Planova logo (client/src/assets/Icon.png) is attached as a CID inline image
and shown in the email header. If the file is missing, emails still send without it.

Email types:
  verify            registration OTP
  email-change      OTP sent to new email address
  password-change   OTP for password change
  forgot-password   OTP for password reset
  welcome           sent on newsletter subscription (no OTP, just confirmation)

To set up emails, fill in SMTP_* values in server/.env (see Section 5).


================================================================================
12. NEWSLETTER
================================================================================

Users subscribe from the bottom of the Home page.
Email is saved to the Subscriber model in MongoDB.
A welcome email is sent immediately after subscribing.

Admin can see all subscribers on the Overview page (with subscribe date).

Routes:
  POST /api/newsletter/subscribe            save email, send welcome email
  GET  /api/newsletter/subscribers          admin only, all subscribers
  DELETE /api/newsletter/subscribers/:id    admin only, remove one


================================================================================
13. PROFILE PICTURES
================================================================================

Users pick an image file (JPG or PNG, max 2MB).
The file is read as a base64 data URL in the browser.
The base64 string is sent to PUT /api/auth/profile as the avatar field.
It is stored directly in MongoDB on the User document.
It is displayed everywhere the user appears: profile pages, sidebar, navbar, admin.

No file storage service is needed — everything stays in MongoDB.

  Access to exhibitor dashboard
  Can set up company profile and contact details
  Change password via OTP on settings page
  Applications and booths still from mock data

ADMIN
  Created only via node seed.js (cannot self-register)
  Access to admin panel at /admin
  Admin login at /admin/login (separate from public login)
  Skips OTP verification (pre-verified)
  Can view all users, activate/deactivate accounts, see newsletter subscribers
