1. WHAT IS PLANOVA
================================================================================

A web platform for managing expos, trade shows, and conferences in Pakistan.

Three user types:
  ATTENDEE  — browse expos, register, view schedule, see exhibitors
  EXHIBITOR — apply to expos, manage booth, build company profile
  ADMIN     — manage the whole platform (users, expos, applications, booths, schedule)


================================================================================

4. HOW TO RUN
================================================================================

Requirements: Node.js v18+, MongoDB (local or Atlas)

1. Install MongoDB (local or Atlas)
2. cd server && npm install
3. cd client && npm install
4. Create server/.env (see Section 5)
5. Get Gmail App Password for SMTP (Google Account > Security > 2FA > App Passwords)
6. Seed the database: cd server && node seed.js
7. Start: cd server && npm run dev (port 5000)
8. Start: cd client && npm run dev (port 5173)
9. Open http://localhost:5173

Vite proxies /api/* to localhost:5000 automatically.

6. DATABASE MODELS
================================================================================

User: name, email, password (bcrypt), role, phone, city, company, category,
      description, website, avatar (base64), isActive, isVerified,
      otp, otpExpiry, otpPurpose, pendingEmail, pendingPassword

Event: organizer, title, description, category, dateStart, dateEnd, venue,
       city, image, status (draft/published/archived), totalBooths

Session: event (ref Event), title, description, speaker, speakerRole,
         type (Keynote/Talk/Workshop/Panel), date, time, duration, room

Exhibitor: user (ref User), event (ref Event), company, contact, phone, email,
           category, city, description, booth, status (pending/approved/rejected),
           rejectReason

Booth: boothId, event (ref Event), type, size, status (available/occupied/pending),
       exhibitor (company name string)

Registration: user (ref User), event (ref Event), status, registeredAt
              Unique index: { user, event } — can't register twice

Subscriber: email (unique)

7. API ROUTES
================================================================================

Base: http://localhost:5000

AUTH (public)
  POST /api/auth/register                  create account, send OTP
  POST /api/auth/verify-otp               verify OTP, activate account
  POST /api/auth/resend-otp               resend OTP
  POST /api/auth/login                    login
  POST /api/auth/admin/login              admin login
  POST /api/auth/forgot-password          send reset OTP
  POST /api/auth/reset-password           verify OTP, set new password

AUTH (protected)
  GET  /api/auth/profile                  get current user
  PUT  /api/auth/profile                  update profile (not email/password)
  POST /api/auth/request-email-change     send OTP to new email
  POST /api/auth/confirm-email-change     verify OTP, swap email
  POST /api/auth/request-password-change  send OTP to current email
  POST /api/auth/confirm-password-change  verify OTP, save new password

AUTH (admin)
  GET  /api/auth/stats                    user count stats
  GET  /api/auth/users                    all users
  PUT  /api/auth/users/:id/status         toggle active/inactive

EXPOS
  GET  /api/expos                         public, published only
  GET  /api/expos/all                      admin, all statuses
  GET  /api/expos/:id                      single expo
  POST /api/expos                         admin, create
  PUT  /api/expos/:id                     admin, edit
  DELETE /api/expos/:id                   admin, delete (auto-deletes sessions)

SESSIONS
  GET  /api/sessions                      public, filter by ?event=id
  POST /api/sessions                      admin, create
  PUT  /api/sessions/:id                  admin, edit
  DELETE /api/sessions/:id                admin, delete

APPLICATIONS
  GET  /api/applications/approved         public, approved exhibitor profiles
  GET  /api/applications                  admin, all applications
  GET  /api/applications/mine             exhibitor, own applications
  POST /api/applications                  exhibitor, submit application
  PUT  /api/applications/:id/approve      admin, approve
  PUT  /api/applications/:id/reject       admin, reject with reason

BOOTHS
  GET  /api/booths                        protected, filter by ?event=id
  POST /api/booths                        admin, create
  PUT  /api/booths/:id/assign             admin, assign exhibitor
  PUT  /api/booths/:id/clear              admin, clear assignment
  DELETE /api/booths/:id                  admin, delete

REGISTRATIONS
  POST /api/registrations                 attendee, register for expo
  GET  /api/registrations/mine            attendee, own registrations
  DELETE /api/registrations/:id           attendee, cancel registration
  GET  /api/registrations                 admin, all registrations

NEWSLETTER
  POST /api/newsletter/subscribe          public, save email + send welcome
  GET  /api/newsletter/subscribers        admin, all subscribers
  DELETE /api/newsletter/subscribers/:id  admin, remove subscriber

HEALTH
  GET  /api/health                        server + DB status

9. AUTH & OTP SYSTEM
================================================================================

Login flow: register > OTP to email > verify > account active > token stored
Login: email + password > token returned > stored in localStorage
Protected routes: PrivateRoute checks localStorage + auth context
Logout: clears localStorage

OTP uses:
  Registration: POST /register > OTP > POST /verify-otp
  Email change: POST /request-email-change > OTP > POST /confirm-email-change
  Password change: POST /request-password-change > OTP > POST /confirm-password-change
  Forgot password: POST /forgot-password > OTP > POST /reset-password


================================================================================
10. PASSWORD REQUIREMENTS
================================================================================

  At least 7 characters
  At least one letter (a-z or A-Z)
  At least one special character (!@#$%^&* etc.)

Enforced on register, forgot password, and password change.
Register and ForgotPassword pages show live hints as you type.


================================================================================
11. EMAIL SYSTEM
================================================================================

All emails sent via nodemailer using SMTP (any provider).
Transporter created fresh on each send so env var changes take effect immediately.
Planova logo attached as CID inline image in the email header.

Email types: verify, email-change, password-change, forgot-password, welcome
Setup: fill SMTP_* values in server/.env


================================================================================
12. NEWSLETTER
================================================================================

Users subscribe from the Home page bottom section.
Email saved to Subscriber model, welcome email sent immediately.
Admin sees all subscribers on the Overview page.


================================================================================
13. PROFILE PICTURES
================================================================================

Users pick an image (JPG/PNG, max 2MB).
Read as base64 in the browser, sent to PUT /api/auth/profile.
Stored directly in MongoDB on the User document.
Displayed in profile pages, sidebar, navbar, admin users list.


================================================================================
14. EXPOS & SESSIONS
================================================================================

Admin creates expos from /admin/expos with title, description, category, dates,
venue, city, image, status (draft/published/archived), total booths.

Only published expos appear on:
  - Public website (/explore-expos)
  - Attendee dashboard (/explore)
  - Exhibitor dashboard (/explore)

Admin creates sessions from /admin/schedule linked to an expo.
Sessions appear on:
  - Public website (/schedule)
  - Attendee dashboard (/schedule)

Deleting an expo automatically deletes all its sessions.


================================================================================
15. EXHIBITOR APPLICATIONS & BOOTHS
================================================================================

Exhibitors submit applications from their dashboard.
Admin reviews from /admin/applications — approve or reject with reason.
Approved exhibitors appear in the attendee Exhibitors page (/exhibitors).
Admin assigns booths from /admin/booths — only approved exhibitors eligible.
Each exhibitor can only be assigned to one booth per expo.


================================================================================
16. ATTENDEE REGISTRATION
================================================================================

Attendees register for expos from their dashboard /explore page.
Registration saved to Registration model in MongoDB (unique per user+event).
My Events page shows registered expos split into upcoming and past.
Cancel button removes the registration.
Cancel button has a red hover effect for clear visual feedback.


================================================================================
17. USER ROLES
================================================================================

ATTENDEE
  Registers through normal signup, OTP verified
  Browse expos, register, view schedule, see exhibitors
  Edit profile, photo, email (OTP), password (OTP)

EXHIBITOR
  Registers by selecting Exhibitor role
  Set up company profile, submit applications
  View own application status (pending/approved/rejected)
  Applications and booths from database

ADMIN
  Created only via seed.js (cannot self-register)
  Admin login at /admin/login (separate from public login)
  Skips OTP verification (pre-verified)
  Full CRUD on expos, sessions, applications, booths, users
