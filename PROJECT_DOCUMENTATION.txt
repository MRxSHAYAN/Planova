1. OVERVIEW
================================================================================
Planova is a platform for managing expos, trade shows, and conferences in
Pakistan. It connects three types of users:

  Admin     -- creates and manages expos, approves exhibitors, assigns booths
  Exhibitor -- applies to expos, manages booth and products
  Attendee  -- registers for expos, views sessions and exhibitors

All data is served from MongoDB. There are no static data files in the app.

4. HOW TO RUN
================================================================================
Prerequisites: Node.js 20+, MongoDB running locally

  # Server (port 5000)
  cd server && npm install && npm run dev

  # Client (port 5173)
  cd client && npm install && npm run dev

The Vite dev server proxies /api/* to port 5000.
For production: cd client && npm run build — serves dist/ statically.

8. DATABASE MODELS
================================================================================
User
  email + role form the unique key (same email can be attendee AND exhibitor)
  Fields: name, email, password (bcrypt), role, phone, city, company,
          category, description, website, avatar, isActive, isVerified,
          otp, otpExpiry, otpPurpose, pendingEmail, pendingPassword
  Index: { email: 1, role: 1 } UNIQUE

Event (expo)
  Fields: organizer (-> User), title, description, category, dateStart,
          dateEnd, venue, city, image, status (draft|published|archived),
          totalBooths, maxAttendees

Session
  Fields: event (-> Event), title, description, speaker, speakerRole,
          type (Keynote|Talk|Workshop|Panel), date, time, duration, room

Registration
  Fields: user (-> User), event (-> Event), status (confirmed|pending|cancelled)
  Index: { user: 1, event: 1 } UNIQUE

Exhibitor (application)
  Fields: user (-> User), event (-> Event), company, contact, phone, email,
          category, city, description, booth (preference), assignedBooth,
          status (pending|approved|rejected), rejectReason
  Index: { user: 1, event: 1 } UNIQUE

Booth
  Fields: boothId (string), event (-> Event), type (Standard|Premium|Corner),
          size, status (available|pending|occupied), exhibitor (company name)
  Index: { boothId: 1, event: 1 } UNIQUE

Product
  Fields: exhibitor (-> User), name, description, price, image, category

Newsletter
  Fields: email, createdAt

10. AUTH & OTP SYSTEM
================================================================================
Registration:
  1. POST /api/auth/register -- creates unverified user, sends 6-digit OTP
  2. User enters OTP on Register page
  3. POST /api/auth/verify-otp -- marks isVerified=true, returns JWT

Login:
  1. User picks role card (attendee or exhibitor)
  2. POST /api/auth/login with { email, password, role }
  3. Server finds user by { email, role }, checks password + isVerified
  4. Returns user object + JWT stored in localStorage as "planova_token"

Forgot password:
  1. User picks role + enters email on ForgotPassword page
  2. POST /api/auth/forgot-password -- finds { email, role }, sends OTP
  3. User enters OTP + new password
  4. POST /api/auth/reset-password

Email change (logged in):
  POST /request-email-change  -> OTP sent to new email
  POST /confirm-email-change  -> email updated

Password change (logged in):
  POST /request-password-change  -> OTP sent to current email
  POST /confirm-password-change  -> password updated

OTP expiry: 10 minutes

11. PASSWORD RULES
================================================================================
  - 7+ characters
  - At least one number
  - At least one special character (!@#$%^&* etc.)

Enforced in:
  server/routes/authRoutes.js   validatePassword()
  client Register.jsx           pwCheck()
  client ForgotPassword.jsx     pwCheck()

12. EMAIL SYSTEM
================================================================================
File: server/utils/sendEmail.js

Nodemailer with generic SMTP. Transporter created once per process.

Email types:
  "verify"           -- account verification OTP
  "email-change"     -- confirm new email address
  "password-change"  -- confirm password change
  "forgot-password"  -- reset forgotten password

Each email is styled HTML with the 6-digit code prominently displayed.

Note: no email is sent when an admin approves or rejects an application.
That is a known limitation (see section 19).

13. MULTI-ROLE ACCOUNTS
================================================================================
Same email can register as both attendee and exhibitor -- two separate User
documents in MongoDB.

Schema: email field is NOT globally unique.
Index:  { email: 1, role: 1 } UNIQUE

Login, forgot-password, and reset-password all accept a "role" field and
query { email, role } to find the correct account.

To apply the index on an existing DB (one-time):
  mongosh planovaDB --eval "
    db.users.dropIndex('email_1');
    db.users.createIndex({ email: 1, role: 1 }, { unique: true });
  "

19. KNOWN LIMITATIONS
================================================================================
These are known incomplete or missing features:

  Bookmarks / saved items
    Bookmarking sessions and exhibitors is local state only (no DB model).
    The SavedItems page shows a placeholder directing users to My Events
    and My Schedule.

  Application status emails
    When an admin approves or rejects an exhibitor application, no email
    is sent to the exhibitor. They can check status in My Applications.
    OTP emails (verify, password reset, etc.) do work.

  Booth change request admin flow
    Exhibitors can request a booth change from My Applications.
    The request appears in the application detail modal in the admin panel
    (shown as "Booth request" badge). However, there is no dedicated admin
    UI action to approve or decline it -- the admin would manually assign
    a new booth from the Booths page.

  Saved items persistence
    No savedSessions or savedExhibitors collection. The bookmark icon in
    MySchedule saves to component state only (lost on page refresh).
